| Модуль репутации 2GIS (отображение) | `/`, `/portal/reputation` |
| Автоматический деплой из ветки `main` в Azure | GitHub Actions |

### Работает только в демонстрационном режиме

| Что | Почему это демо |
|---|---|
| Все кейсы, суммы, аптеки «Алматы-3», «Астана-7», контрагенты | Записаны в код (`demo.ts`), к реальным системам не подключено |
| Агенты контроля | Существуют как описания, расчётов по реальным данным не делают |
| Согласования | Хранятся в браузере, **пропадают при перезагрузке** |
| Журнал действий | Не сохраняется, не защищён от изменений |
| Роль согласующего | Выбирается кнопкой — нет входа и проверки прав |
| Подсказки МОЗГ, страница «Совет директоров» | Статический текст |
| «AI-генератор ответов» на отзывы | Шаблонные тексты, без ИИ-модели |
| Рейтинги и отзывы 2GIS | Внесены в код вручную, автообновления нет |

| Доступы к агрегаторам, маркетплейсам, интернет-аптеке | I |

## Шаг C. Инфраструктура

Срок: 1–2 недели. Ответственный: технический руководитель.

**Решения, которые нужно принять (письменно, в группе проекта):**
- [ ] **Где сервер.** Рекомендация: для разработки и пилота на демо-данных —
      любое облако; до подключения реальных данных 1С — сервер или облако
      в Казахстане (по заключению шага B).
- [ ] **Хостинг приложения.** Рекомендация: контейнер с постоянно работающим
      процессом (нужен для напоминаний, опроса Bitrix24, расписаний).
      Текущий Azure Static Web Apps оставляем только для демо-версии.
- [ ] **Способ входа сотрудников.** Рекомендация: через учётные записи
      Bitrix24 (одна учётка для портала и задач).

**Что подготовить (ориентир для старта, уточняется после пилота):**

| Ресурс | Параметры | Для чего |
|---|---|---|
| Сервер приложения | 4 vCPU, 8–16 ГБ RAM, 100 ГБ SSD, Linux, Docker | Портал, API, фоновые задачи |
| PostgreSQL 15+ | 2 vCPU, 8 ГБ RAM, 100 ГБ, ежедневный бэкап, хранение 30 дней | Кейсы, журнал, справочники |
| Файловое хранилище (S3-совместимое) | 200 ГБ, версионирование, запрет удаления на 1 год | Доказательства |
| Домен | например `audit.sadykhan.kz` | Адрес портала |
| SSL-сертификат | Let's Encrypt или корпоративный | HTTPS |
| Резервная копия | Ежедневно, копия в другом месте | Восстановление |

**Действия:**
- [ ] Создан сервер и база; доступ к базе только с сервера приложения.
- [ ] Создано хранилище файлов.
- [ ] Настроен домен и HTTPS.
- [ ] Разработчику выдан доступ к серверу (SSH-ключ) и к репозиторию GitHub
      `kad271190-bot/sadykhan-dashboard` с правом записи.
- [ ] Секреты внесены (см. раздел «Секреты»): `DATABASE_URL`,
      `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `AUTH_SECRET`.
- [ ] Включён мониторинг доступности и оповещение технического руководителя.
- [ ] Проверено восстановление базы из резервной копии (пробное).

**Критерий готовности:** приложение открывается по HTTPS на вашем домене,
пробное восстановление из бэкапа прошло.

## Шаг F. Доступ к 1С

Срок: 2–4 недели. Ответственный: специалист 1С + технический руководитель.
Принцип: **только чтение**, система контроля ничего не пишет в 1С.

**Что сообщить (шаблон [`12_integrations.csv`](templates/12_integrations.csv)):**
- [ ] Перечень баз 1С: конфигурация и версия (например, «Розница 2.3.x»,
      «УТ 11.5.x», «БП 3.0.x», «ЗУП 3.1.x»), на каком сервере, СУБД (MS SQL / PostgreSQL / файловая).
- [ ] Выбранный способ доступа (один из):
  1. **OData** (стандартный интерфейс 1С) — публикация на веб-сервере и
     включение нужных объектов. Предпочтительно.
  2. **HTTP-сервис** в расширении конфигурации — если OData недоступен.
  3. **Регламентная выгрузка** JSON/CSV на SFTP каждые 15–60 минут.
  4. **Копия базы только для чтения** (реплика СУБД) — если остальные варианты невозможны.
- [ ] Создан пользователь 1С с правами только на чтение (например, `ai_audit_ro`).
- [ ] Обеспечен сетевой доступ с сервера системы к 1С (VPN или белый IP).
- [ ] Секреты внесены: `ONEC_<БАЗА>_URL`, `ONEC_<БАЗА>_USER`, `ONEC_<БАЗА>_PASSWORD`.

**Какие данные нужны из 1С** (специалист 1С указывает имя объекта в вашей конфигурации):

| Данные | Для каких проверок | Частота |
|---|---|---|
| Чеки ККМ, возвраты, аннулирования, отложенные чеки, скидки (с кассиром и временем) | Антифрод касс | 15–60 мин |
| Операции программы лояльности | Антифрод лояльности | 1 час |
| Остатки с сериями и сроками годности по аптекам и складам | Сроки, отзыв серий | 1 раз в сутки + по запросу |
| Инвентаризации, списания, пересорт, перемещения | Ревизии, склад | 1 раз в сутки |
| Реализация оптовым клиентам, оплаты, взаиморасчёты, кредитные лимиты и история их изменений | Дебиторка | 1 час |
| Поступления товаров, цены поставщиков, спецификации | Закупки | 1 раз в сутки |
| Заказы интернет-аптеки и агрегаторов, как они отражены в 1С | Сверка e-commerce | 1 час |
| Платёжные поручения, договоры, авансовые отчёты | Финансовый контроль | 1 раз в сутки |
| ЭСФ, акты сверки | Аудит бухгалтерии | 1 раз в сутки |
| Сотрудники, приказы, табель, сертификаты (ЗУП) | Кадровый аудит | 1 раз в сутки |
| Пользователи 1С, их роли, журнал регистрации | Аудит доступов | 1 раз в сутки |

**Критерий готовности:** с сервера системы успешно читается тестовая выборка чеков одной аптеки за 1 день.

## Шаг G. ОФД и кассы

Срок: 1–2 недели. Ответственный: главный бухгалтер.

- [ ] Название оператора фискальных данных (по договору) и номер договора.
