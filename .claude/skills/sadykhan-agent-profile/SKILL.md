# Профиль ИИ-аудитора

Где всё живёт (`demo/sadykhan-ai-ecosystem.html`):
- `DIRS` — направления и подразделения (`units[].agents` — какие агенты закреплены);
- `AGENTS` — карточка агента: `id, name, short, icon, kind, rules, spec, area, know, procs, procU, expert, limits`;
- `RULES` — контрольные процедуры кодом (`u, name, sev, auto, cat, norm`) и их реализация в `detect()` и `verify()`;
- `MATRIX` — ответственный по задачам; `PROCESS_SCOPES` — процессы для автономного ИИ-аудита;
- `PROFILES` — профессиональный профиль (схема — `profile-schema.md` рядом с этим файлом);
- `SYS` — системы-источники и их статус подключения; `PROC_DAILY` — проверки по реальной выгрузке.

## Шаги
1. **Не дублировать.** Найти, нет ли уже агента с этой зоной (`grep -n "id:'" demo/sadykhan-ai-ecosystem.html`). Если зона близкая — расширить существующего, а не создавать второго. Агент закрепляется за одним основным подразделением; остальные связи — в `procU`/списке подразделений, не копией карточки.
2. **Оргструктура.** Подразделение брать из `DIRS`. Нового подразделения нет в подтверждённой структуре — добавлять только с пометкой «проект» (правило CLAUDE.md) и сообщить пользователю.
3. **Карточка в `AGENTS`** — все поля; `limits` — что агент НЕ делает (только чтение бизнес-систем, без выводов о вине).
4. **Профиль в `PROFILES`** по `profile-schema.md`. Обязательно конкретика: в каждой ежедневной процедуре — что проверяется, правило и порог со ссылкой на норму, данные, ожидаемый результат. `code` — только если такая процедура реально есть в `RULES` и в `rules` агента; иначе `null` (будет показана как «Запланирована»).
5. **Если процедура должна работать в демо** — добавить код в `RULES`, логику в `detect()` и независимую перепроверку в `verify()`, тестовый случай в `buildWorld()` (нарушение через `gt(...,'violation',...)` и, по возможности, ловушку `'decoy'`).
6. **Источники**: `sources[].s` — код из `SYS`; новый источник — добавить в `SYS` с `plan` (как и когда будет подключён). Не подключённое никогда не помечать как работающее.
7. **Проверка схемы** — команда в конце `profile-schema.md`; должны напечататься все ID без строк «нет …».
8. **Выпуск** — навык `sadykhan-publish` (он включает `sadykhan-risk-check` и автотест всех профилей во всех ролях).

## Критерий результата
- агент виден в своём подразделении и в списке «ИИ-агенты», профиль открывается на всех вкладках без «undefined» (автотест);
- счётчики «работают в демо / по реальным данным / запланированы» совпадают с фактом;
- руководитель розницы не видит корпоративных агентов (автотест проверяет);
- ни один существующий агент, процедура или профиль не удалены (сравнить `AGENTS.length` и список `PROFILES` до и после).
