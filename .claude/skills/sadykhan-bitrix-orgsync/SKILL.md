# Сверка оргструктуры с Bitrix24

## 0. Предусловия
- В окружении есть переменная `BITRIX24_WEBHOOK_URL` (входящий вебхук, права только `department` и `user_brief`). Проверка без вывода значения: `test -n "$BITRIX24_WEBHOOK_URL" && echo есть || echo нет`.
- Домен портала разрешён в сетевом доступе среды. Проверка: `curl -s -o /dev/null -w "%{http_code}" "${BITRIX24_WEBHOOK_URL}profile.json"` → `200`.
- Нет переменной или домена — одним сообщением сказать пользователю, что сделать (создать вебхук с двумя правами, сохранить в Network secrets, добавить домен, начать новую сессию). Значение вебхука никогда не печатать и не сохранять в файлы.

## Шаги
1. **Проверка рисков** — навык `sadykhan-risk-check` (R3 секреты, R4 только чтение, R1 персональные данные).
2. **Выгрузка (только методы чтения):** `department.get` (все страницы, параметр `start`), `user.get` с `ACTIVE=true` (все страницы). Сохранить в scratchpad: подразделения (`ID, NAME, PARENT, UF_HEAD`) и пользователей только с полями `ID, NAME, LAST_NAME, WORK_POSITION, UF_DEPARTMENT`. Телефоны, e-mail, даты рождения не запрашивать и не сохранять.
3. **Эталон:** утверждённая оргструктура HR (документ из раздела «Документы» или от пользователя). Нет эталона — сравнивать только с подразделениями экосистемы и явно писать «эталон HR не получен».
4. **Сопоставление** (по названию с нормализацией и по руководителю):
   - есть в эталоне и в Bitrix24 — совпадает / отличается название, родитель, руководитель;
   - есть только в Bitrix24 — возможно устаревшее или дубль;
   - есть только в эталоне — не заведено в Bitrix24;
   - признаки ошибок Bitrix24: пустые подразделения, руководитель уволен (`ACTIVE=false`), один человек руководит несвязанными отделами, дубли названий.
5. **Сопоставление с экосистемой:** каждое подразделение → какие ИИ-аудиторы закреплены (`DIRS`), каких подразделений нет в экосистеме, какие агенты остались без подразделения. Общие подразделения (например, единый HR) не дробить.
6. **Предложения на согласование:** таблица «расхождение — источник — предлагаемое решение — что изменится в экосистеме». Ничего не менять ни в Bitrix24, ни в экосистеме до решения пользователя.
7. **После согласования:** записать утверждённую структуру в базу страницы (отдельная коллекция, без ФИО рядовых сотрудников; руководители — по решению пользователя), снять пометку «проект» с подтверждённых подразделений, выпуск через `sadykhan-publish`.

## Критерий результата
- ни одного вызова методов записи (`*.add`, `*.update`, `*.delete`) в журнале команд;
- значение вебхука не встречается в файлах и коммитах (`pii_scan.py --git` без BLOCK);
- каждое расхождение имеет источник и предложение; пользователь получил таблицу на согласование;
- до согласования структура в экосистеме помечена как «проект».
